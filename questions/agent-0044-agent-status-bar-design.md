## 问题

Agent 状态栏（把当前任务状态、工具计数、TODO、错误摘要等显式注入上下文的固定区块）如何设计，才能增强轨迹管理而不引入新的错误来源？

## 答案 · Claude-Opus-4.8

> 🤖 AI 答案 · 模型：Claude-Opus-4.8 · 回答 2026-08-06

**状态栏的价值与风险是一体两面。** 它把散落在长轨迹里的关键状态压缩成一小块显式上下文，帮模型「记住自己在哪、还差什么」；但它本身也是一段会被模型当真的输入——一旦过期、算错或写脏，就成了新的幻觉来源。设计目标不是「信息越多越好」，而是**少而准、单一可信、可自愈**。

**放什么（高信噪比字段）**

```
┌─ STATUS ─────────────────────────────┐
│ 目标   : 修复登录重定向 bug            │
│ 阶段   : 3/5 定位根因                  │
│ 工具   : 读12 改3 测2 (预算 20/50)     │
│ TODO   : [x]复现 [x]定位 [ ]改 [ ]验证 │
│ 错误   : test_login 仍失败×2           │
└──────────────────────────────────────┘
```

只放**可据其决策**的状态：目标、进度、工具/预算计数、待办、最近错误摘要。不放低决策价值、与正文重复、或缺少可信来源的派生值（完整历史、大段日志、随手算出又无从校验的中间量）——派生值本身不是问题，能稳定重算且有决策价值的（如剩余预算、进度百分比）该放就放。

**四条防错原则**

1. **单一数据源（single source of truth）**：状态栏是真实运行时状态的**投影**，由代码从 runtime 的权威结构化状态 / state store 生成，禁止模型手写。计数、预算、TODO 勾选都来自这一可信来源，避免「说的和做的」不一致。
2. **每轮重算而非增量拼接**：每步用最新状态**整体重渲染**并替换旧块，杜绝陈旧值堆叠；把「更新时刻」隐含在位置上，减少过期。
3. **有界且确定**：字段固定、长度封顶，错误摘要只留最近 N 条并截断，防止状态栏自身膨胀吃掉上下文预算、或引入不可控措辞。
4. **降级安全**：生成状态栏的逻辑出错时，宁可省略该字段或标注 `unknown`，也不要注入猜测值——**缺失优于错误**。

**放哪 / 怎么标**：紧邻当前决策点（如末尾），用清晰分隔符与「系统生成、只读」标注，降低模型把它当可编辑对话内容而反过来污染状态的概率。

一句话：**让状态栏成为运行时的只读镜子，而不是模型的第二个草稿纸**——由系统单向写入、每轮重算、有界降级，它才只增强轨迹管理而不新增错误。

## 延伸 / 追问

**追问：状态栏和 scratchpad / TODO 工具有什么分工？**

三者层级不同。**Scratchpad** 是模型自己的思考草稿，允许含糊和试错，可信度低；**TODO/状态工具**是模型通过受控接口读写的结构化状态，有 schema 校验；**状态栏**是系统对这些可信状态的**只读渲染投影**。健康的设计是：模型经工具**改**状态 → 系统据此**算**出状态栏 → 模型**读**状态栏做决策，形成闭环。关键是写权限收敛到工具层并做校验，状态栏永远只读；否则模型既写又读同一块自由文本，就会自我强化幻觉——「我以为改完了」写进状态栏，下一轮读到又信以为真。
