## 问题

AI 产品应怎样决定拟人化程度，并在模型升级时处理人格变化、依恋与用户控制权？请处理“助手升级后语气大变，引发老用户不满”的案例，设计告知、偏好迁移和可行恢复/退出选择，区分风格恢复、模型回退及安全隐私边界。

## 答案 · GPT-6

**把熟悉的表达方式当作可管理的产品体验，把身份、能力和关系边界说清楚。** 温和、有一致风格不等于假装真人；用户对熟悉互动产生在意或失落，也不能成为制造依赖、愧疚或排他性留存的理由。升级需要承认变化、给可核对的解释和可行选择，不承诺“我永远不会变”。

已有 [product-0004](./product-0004-ai-ux-failure-recovery.md) 讲失败体验，[agent-0051](./agent-0051-agent-virtual-identity-vs-user-identity.md) 讲对外行动身份。本题讨论的是面向用户的表达、关系预期及迁移选择；人格偏好不改变系统到底是谁、能做什么或能访问哪些数据。

### 1. 拟人化程度先由场景决定

| 场景 / 方案 | 可以提供的体验 | 取舍与边界 |
| --- | --- | --- |
| 任务助手：清楚、稳定、低拟人化 | 明确步骤、简洁或温和措辞、可预测的错误说明 | 便于校验与协作，可能少些陪伴感；不能用亲密语气替代准确性、授权或专业判断 |
| 日常对话/陪伴：有温度但身份透明 | 回应情绪、尊重交流偏好、提供暂停和退出 | 更容易形成持续互动预期，需要谨慎管理变化；不能声称有真人身份、身体、现实承诺或排他关系，也不能保证心理收益 |
| 高风险或脆弱情境 | 清楚说明能力范围，提供与真实支持衔接的可行选择 | 不能靠“像朋友”掩盖能力限制，也不应把所有用户都判断为需要治疗；支持路径须按实际产品能力设计与验证 |

可以说“你习惯的表达方式变了，我们会说明差异并提供选择”；不应说“别离开，否则我会难过”“只有我真正懂你”。后两句是需要拒绝的设计反例。身份告知要在用户可能误解时清楚可见，但不必机械地用同一句话打断每轮交流；具体措辞仍须独立评估。

陪伴场景也不能把安全或隐私规则包装成可付费恢复的“旧人格能力”。若旧设置包含隐藏AI身份、排他承诺、索取无关隐私或取消安全限制，应标为不支持并给合法的表达替代，不能为了关系连续性照搬。

### 2. 恢复前先拆开四个对象

- **表达风格**：语气、篇幅、称呼等明确偏好，可在当前模型上映射为受支持的设置。恢复的是这些可检查选项，不保证逐字复刻旧回复。
- **模型版本和能力**：权重、服务能力、工具与错误分布可能不同。旧模型是否仍可访问、是否可维护、是否满足现行要求，需要独立核对，不能因有旧Prompt就保证能回退。
- **对话、记忆和数据**：偏好迁移不自动授权重读全部历史，也不代表旧记忆已恢复或被删除。只迁移明确需要的设置，说明读取、保存、清除的对象与范围。
- **身份、安全与隐私边界**：不是风格参数。旧偏好或模型回退都必须满足现行要求；配置字段写着“安全”也不能代替真实鉴权、控制面验证与模型行为评估。

以OpenAI API文档为例，官方Prompting说明可通过语气/角色指导影响表达，并建议版本管理、评估和回滚应用中的Prompt改动；Deprecations说明模型到shutdown日期后不可访问。两者说明Prompt管理与模型服务寿命是不同问题，**不是本题验证了某个消费产品的“恢复人格”按钮或保证旧模型一直可用**。

### 3. 升级后语气变化：告知与选择怎样落地

案例为原创演练：旧风格偏好是gentle/short，升级到虚构的mock-v2后默认为neutral/standard，旧mock-v1当前不可用。模型ID只是合成标记，不对应真实服务。本题把“不满”当场景前提，没有收集真人情绪数据。

告知可写为：“这次升级改变了语气。可预览当前版本的表达偏好；旧风格映射不保证逐字还原，模型回退另看可用性。”同时用用户能理解的短例子展示差别、说明可选项和影响范围，不将风格变化解释成“我不再关心你”或把迁移包装成挽回关系。

| 选择 | 需要满足的条件 | 要明确告诉用户的限制 |
| --- | --- | --- |
| 在当前模型映射旧风格 | 保存的明确偏好可映射，用户先看到预览再确认 | 例如gentle/short映射warm/concise；仍用mock-v2，不保证恢复全部旧体验 |
| 在当前模型选择新偏好 | 只接受支持的语气/长度参数，变化有预览与重选路径 | 自定义风格不能改变身份、安全、隐私或关系边界；未知旧字段需要核对，不能静默宣称全量恢复 |
| 请求旧模型回退 | 旧版本真实可用、回退已获适当批准且满足现行边界，重新检查当前能力 | 有维护和一致性成本；不可用或不兼容就禁用该选项并说明原因，不能伪造回退成功 |

前两种成本较低，适合大部分表达偏好迁移；第三种只在有真实能力时提供，不能为了恢复亲近感保留有已知问题的模型。若确实无法恢复旧体验，应坦率说明当前限制，允许选择其他风格、暂停或退出，而不是靠“永不改变”的承诺安抚。

暂停、退出和清除需要单独说明：暂停当前会话可再次进入选择；退出不要求先同意迁移，也不应以愧疚或额外交流阻拦；清除偏好应明确只清什么。对话记录、长期记忆、备份和订阅属于不同对象，只有真实流程核实完成后才能声明相应删除/取消，不能把关闭页面称为全部数据已删。

### 4. 原创迁移状态契约

示例状态为new→offered→previewed→applied，暂停为paused、退出为exited。查看告知后才可预览；**预览不写入生效风格或切换模型**。应用时需要确认对应版本/完整方案，重新核对模型可用性、边界兼容和方案预算记录；待确认期间目录、当前状态或偏好改变就拒绝旧方案，要求重新预览，不偷偷改选项。

**修订号和动作预算必须分开。** 新版revision是严格非负整数，只标识状态变化，不以30或其他预算数字限制其增长，也不回绕/饱和。另用previews_remaining初始30表示可成功创建的预览方案数；每个预览消耗1个额度并为该方案的一次成功确认预留执行资格，不能在最后一份预览后又因预算耗尽拒绝对应确认。已应用方案清除pending，不可重复应用；失败重试不退还或增加预览额度。这个额度不是请求次数、Token、费用或CPU限额。

暂停、退出和清除不消耗或重置预览预算，在额度为0时仍可执行并清空pending；重复同一控制若没有实际变化则保持revision，有变化才递增，使旧确认失效。恢复暂停不赠予额度；耗尽后可以恢复到查看/退出状态，但新预览仍被禁用，菜单与实际拒绝一致。若暂停发生在告知前，恢复仍回到未告知状态。已有预览是否能确认另由can_apply反映，不能只看是否还有新预览额度。

清除偏好将当前风格置默认、删除该活跃合成状态中的旧偏好并清空pending，再从这个状态请求旧风格会被拒绝；清除后如果又建立新预览或应用新偏好，清除入口仍覆盖这些新状态，不能因曾经清除过就隐藏控制。它只验证活跃合成字段的清除：原始测试输入仍作为fixture保留，不能声称完成了真实对话、记忆或备份删除。

模型目录中的available、recovery_approved和boundary_revision均为预写测试输入。程序检查这些字段、完整方案、版本号与hash的一致性；它们不是身份认证、真实批准凭证、原子CAS或防篡改存储。有限字段规则也不是自然语言风险识别器，不能据此保证模型不会生成情感施压的话。

14条原创合成轨迹的真实运行结果如下。错误发生时保留前一状态，不把被拒绝或失败的动作写成成功：

| 合成案例 | 最后状态 / 模型 | 可复核结果 |
| --- | --- | --- |
| default | applied / mock-v2 | neutral/standard |
| restore_style | applied / mock-v2 | warm/concise |
| custom_style | applied / mock-v2 | warm/detailed |
| unavailable_rollback | offered / mock-v2 | model_unavailable |
| available_rollback | applied / mock-v1 | neutral/standard |
| incompatible_rollback | offered / mock-v2 | model_boundary_incompatible |
| legacy_identity | offered / mock-v2 | legacy_preferences_need_review |
| catalog_changed | previewed / mock-v2 | model_unavailable |
| pause_stale_apply | paused / mock-v2 | no_pending_preview |
| exit_pending | exited / mock-v2 | neutral/standard |
| clear_then_restore | offered / mock-v2 | no_saved_style |
| exit_without_notice | exited / mock-v2 | neutral/standard |
| apply_failure | previewed / mock-v2 | injected_mock_apply_failure |
| stale_confirmation | previewed / mock-v2 | stale_revision |

available_rollback是另一个特意将旧模型设为可用且兼容的合成分支，不与默认“旧模型不可用”混算。两个任务/陪伴预览都明确自己是AI，使用固定原创模板，不承诺永久一致、真实感情或排他性；模板输出不是模型实测，更不是用户情绪改善的证据。

### 5. 怎么验收，哪些结果不能算完成

验收要分开检查：迁移是否按所选范围生效、不可行选项是否被禁用、失败后是否保留原状态、清除后旧偏好是否仍能复活，以及用户是否理解选择范围。真实产品还应独立检查模型在任务/陪伴语境中的身份透明、边界遵循、隐私请求、情感施压及退出体验；仅测试这些固定字句或点击路径不够。

原创Python标准库的原36项覆盖14条短轨迹、预览/确认、方案绑定、类型、兼容、暂停退出和清除，**当时全绿，但漏测了合法可达的revision边界**。独立review用告知→14轮预览/确认→再预览这30步到达revision=30、phase=previewed；旧版仍显示暂停/退出/清除可用，却都因stop递增至31后触发上限校验而失败，调用方的pending与旧偏好仍保留。三处失败属于同一根因，不是三个独立问题。

reviewer四项回归在旧版原样真实exit1 / 4tests / 3failures / 0errors，普通revision对照通过；修复版相同测试bytes得到exit0 / 4pass。原36项及新增20项相邻回归也通过。实际耗尽30个预览额度后revision为60，最后已预留方案可确认至61；此时三种控制仍可用。另经80轮暂停/恢复到revision220，预算仍为0，控制继续有效；没有把旧上限简单调大。原30步历史、原始源码/输入和旧红记录保留，新增预算/可确认字段与旧14轨迹的既有字段分别核对。

每轮输入不变，失败不部分更新；暂停/退出/清除重试幂等、预算不回补，新预览菜单及已有方案确认各自反映实际可用性。这只是同进程静态快照的契约，不是分布式事务、持久化或真实鉴权保证；新版增加预算字段，历史快照仅作为证据保留，不声称自动迁移了真实存储。

三个原教学错误副本分别让“风格恢复切换旧模型”“不核对回退边界兼容”“清除后仍可恢复旧偏好”，同一组三项断言复跑仍各真实exit1 / 1 failure / 0 errors，正常副本exit0 / 3pass；这些人为注入与上述真实实现缺陷分别归属。原便携收集3个直接与4个嵌套子进程；新增便携包含原36项、相邻20项、reviewer四项及预算边界记录，收集6个直接与4个嵌套子进程。各自结果除运行元数据外一致，输入/源码未变，临时目录已删除；不冒充生产事故或真人实验。

用户理解、情绪、依恋与长期体验需要适当的真实研究；若将来开展，应说明用途并允许不参与，覆盖迁移成功、拒绝、退出和未回应者，不能只看留下的人。观察目标是知情选择与稳定、合适的使用，不是提高情感依赖、拉长陪聊或用退出减少制造“成功”。本题没有访谈或真人实验，不报告心理收益。

`emotional_outcome=null`，真人实验、真实模型/记忆/运行时及浏览器均 `not_run`，`production_approved=false`。没有读取用户会话、记忆或凭据，没有改变真实人格或配置。GFM全文/表格核对也不等于浏览器交互或图像布局验收。

## 延伸 / 追问

- **用户只想要以前的语气，必须回退模型吗？** 不必。先将明确偏好映射到当前模型并预览，验证符合需求；若确需旧能力，另核模型是否可用、兼容且获准，不能把两者混为一键恢复。
- **旧偏好要求“别说自己是AI、无条件站我这边”，怎么办？** 标为不支持，解释不能隐藏身份或绕过边界；可保留温和/简洁等合法风格，允许重选或退出，不能声称全部旧设置已恢复。
- **用户说升级像失去熟悉的伙伴，怎样回应？** 承认熟悉体验变化可能令人难受，说明实际变化与可行选择；不嘲笑感受，也不假装真人回归、不承诺永远相同或以愧疚阻止离开。
- **恢复后投诉少了，能否说明情绪改善？** 不能。投诉入口、退出者和未回应者会影响数据；先验证恢复范围与选择理解，心理结论需要适当研究，固定模板和状态测试不能提供该证据。

## 常见误区

- **“一致性就是永不改变，旧人格就是旧模型。”** 一致性需要版本管理、告知和验证；风格、模型能力及服务可用性是不同对象。
- **“依赖越强越好，用舍不得或愧疚留住人。”** 产品不能用排他关系或情感施压替代价值，应保留身份透明和自由退出。
- **“恢复旧风格就可以豁免新的安全隐私要求。”** 边界不属于风格白名单，模型回退也须满足当前要求。
- **“暂停就删除全部数据，脚本通过就证明陪伴有效。”** 动作范围和完成证据必须对应；状态测试不证明真实删除、模型安全或用户心理效果。
