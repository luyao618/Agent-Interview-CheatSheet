## 问题

持续进化的系统里，Agent 可以自己写新工具、改 prompt，甚至更新验证器和评测集。此时「谁来约束它」就成了循环——它能改的东西越多，约束越可能被它自己改掉。哪些东西必须放进它改不到的信任根？权限边界、代码边界和发布流程分别怎么设计？

## 答案 · Claude-Opus-4.8

> 🤖 AI 答案 · 模型：Claude-Opus-4.8 · 回答 2026-08-12

**核心原则一句话：分离「提议权」与「授权权」。** Agent 可以提议任意变更（写工具、改 prompt、甚至改验证器），但**不能批准、签发、或验证自己的变更**。信任根不是「一份不可变的配置」，而是**「Agent 无法凭自身行为改变的那组决定」**。

**一、哪些必须进信任根（TCB）**

- **签名密钥与发布通道**：私钥放 KMS / HSM，Agent 只能**请求签名**、拿不到密钥；无签名的产物不予加载。
- **权限模型与安全策略**本身，以及「谁能改这些策略」的元规则。
- **验证器与评测真值集**：验证器由人签发、版本固定；真值集对 Agent **只读且部分不可见**（保留 holdout），否则它会优化到评测上（Goodhart）。
- **审计日志**：append-only，Agent 无删除 / 改写权限。
- **沙箱与隔离层自身**（被约束者不能重写约束机制）。

```
┌── 信任根（Agent 改不到）────────────────┐
│ 密钥/签名 · 权限策略 · 验证器 · holdout │
│ 审计日志(append-only) · 沙箱实现        │
└────────────┬───────────────────────────┘
   只读约束  │  签发/门禁          ▲ 变更需 m-of-n 人工签名
             ▼                     │
  Agent ──提议──► 候选产物 ──外部验证──► 人审 ──签名──► 灰度 ──可回滚
   （可改：工具代码、prompt、策略参数）      ✗ 不可自签发
```

**二、权限边界：靠身份与凭证，不靠自觉**

Agent runtime 用**独立的低权身份**运行：对策略仓库、密钥、CI 配置一律无写权限。关键是**不能只在 prompt 里写「你不许改 X」**——那是建议不是边界；必须落到 IAM / 文件系统 / 仓库保护分支上，让越权在**机制层**失败。

**三、代码边界：验证器与被验证物必须分离**

分离到不同仓库、不同进程、不同发布流水线，且验证器不加载 Agent 可写路径下的代码。**最容易漏的是「传递闭包」**：Agent 改不了验证器，但如果它能改验证器依赖的某个库、CI 脚本、测试夹具或 prompt 模板，就等价于改了验证器——**凡能影响验证结果的东西，都属于 TCB**。划边界时应沿依赖链倒推，而不是只看那个叫 `verifier` 的文件。

**四、发布流程：提议—验证—审批—签发—灰度—回滚**

变更一律走**不可原地改写**的流水线：产物不可变、带 provenance（谁提议、基于哪代、过了哪些门禁）；高风险变更（触碰权限、外部副作用、信任根本身）强制 human-in-the-loop；灰度上线并保留一键回滚。**绝不允许「生成者即签发者」**。

**一句话：** 信任根的本质不是「锁死一堆文件」，而是**让 Agent 在机制上拿不到「批准自己」的能力**——把密钥、验证器、真值与审计放到它的权限之外，并沿依赖闭包封住所有能间接影响验证结果的路径。

（与 agent-0053 的分工：那题讲自举系统的**代际退化**如何抑制，信任根只是其中一道防线；本题专讲**信任根边界本身**怎么划、怎么落地。）

## 延伸 / 追问

**追问：信任根完全冻死，Agent 就没法进化了；「可演进」和「不可篡改」怎么兼顾？**

**分层**，而不是二选一。① **极小的不可变核心**：密钥、审批规则、审计机制、以及「如何修改信任根」的元规则——这层只应人工变更，且门槛最高（m-of-n 多人签名 + 冷却期 + 全量回归）。② **可演进的外层**：验证器、评测集、工具白名单、资源配额——允许随任务演进，但每次变更必须由核心层**签发**，且带版本与回滚点；评测集应定期轮换以防过拟合（轮换本身由人控制）。③ **给 Agent 一条合法的扩权通道**：不要逼它绕路——用**声明式能力申请**（说明用途、范围、时限），审批后签发**限定 scope、带 TTL、默认过期**的临时凭证，事后审计留痕；这比「一刀切冻结 + Agent 想办法绕过」安全得多。④ **把信任根变更本身当作被监控的信号**：变更频率异常上升、或总是朝「放宽约束」方向，本身就是需要人介入的告警。核心是：**演进发生在信任根之下，而不是通过修改信任根来实现**。
