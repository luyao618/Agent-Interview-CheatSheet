## 问题

AI 文本检测器的分数能否证明作者身份，如何评估误报并设计合理使用边界？请假设AI文本占比、误报率和召回率，计算被标记文本的precision，并说明跨语言、改写、未知标签及申诉证据如何处理。

## 答案 · GPT-6

**检测分可以是特定条件下的筛查信号，不能直接证明谁写了文本，更不能独立证明违规。** 先定义要识别的事件、适用分布和阈值，再核对误报、漏报与base rate；高后果决定还需要独立的过程证据、明确规则和可申诉的人工判断。

[engineering-0014](./engineering-0014-agent-benchmark-leakage-resistant-evaluation.md) 讨论评测污染，[product-0009](./product-0009-trust-calibration-confidence.md) 讨论概率校准和证据表达。本题补充文本来源检测的取证限度，不把文风、检测分或对写作过程的猜测当身份认证。

### 1. 分数、类别概率、作者身份是三件事

检测器可能利用训练得到的分布特征、语言模型似然等统计信号，也可能依赖特定生成流程的水印或已知文本匹配。方法的事件定义、适用输入、威胁模型和证据强度不同，不能统称为“看起来像AI”。流畅、工整或词汇受限都可能出现在人类文字中；低分也可能来自分布外输入或生成文本的后续修改。

显示的“90%”可能是分类器输出、某个指标的映射或被标记片段占比。先读该工具对单位、阈值和有效文本范围的定义，不能擅自把它改名为“作者有90%概率用了AI”。即便某分数经过了独立校准，也只对应约定标签、版本和验证分布下的频率含义；迁移到新语言、题材、长度或写作工具后需重新验证。

例如先将事件A定义为“按本评估协议归入AI主要生成文本类”，而不是“作者是某人”或“作者作弊”。语法辅助、人机共同创作、翻译或来源不清可能不满足二分类定义，应单列mixed/unknown并约定标注流程。作者身份、工具使用是否获准、主观意图和任务质量需要不同证据。水印或来源记录也须核查覆盖范围、完整性及伪造风险，不能跨越这些事件直接处分个人。

不能从有误报反推所有检测方案永远无效。Sadasivan等论文摘要明确承认检测器在特定设置下有效，并研究其在改写等对抗条件下的不同敏感性；本题只采用这个条件化结论，不把未读的全文理论外推为普遍不可能性。[2]

### 2. 用base rate推导标记后的precision

设A为约定的AI文本类，“+”为超过事先固定阈值被标记。令 `p=P(A)` 为目标文本集合的base rate，`r=P(+|A)` 为recall/TPR，`f=P(+|非A)` 为FPR，则：

`P(A|+) = rp / [rp + f(1-p)] = TP / (TP+FP)`。

FPR的分母是实际非A文本，`FP/(FP+TN)`；recall的分母是实际A文本，`TP/(TP+FN)`。二者都不是precision的分母。`P(+|A)` 与 `P(A|+)` 不能互换，`1-FPR`也不是被标记者的可信度。分母为0时precision未定义，应输出null/无法估计；无A或无非A样本时，样本recall或FPR也可能无法估计。

**原创假设**：目标集合N=10000，AI类占1%，recall为80%，FPR为5%，且这些率适用于相同阈值、语言、任务和采样单位。这个理论集合假定来源可完整二分类，检测只有正/负输出，没有mixed/unknown、拒判或失败。期望AI类100篇，TP=80、FN=20；非AI类9900篇，FP=495、TN=9405。被标记575篇，其中AI类占 **80/575≈13.91%**。这是给定假设的期望计数，脚本没有读取或检测一万篇文章；有限样本的实际计数还会波动。

| 合成假设（N=10000） | AI占比 | recall | FPR | 期望TP / FP | 标记后precision |
| --- | --- | --- | --- | --- | --- |
| low_base | 0.01 | 0.80 | 0.05 | 80 / 495 | 13.9130% |
| base_10 | 0.10 | 0.80 | 0.05 | 800 / 450 | 64.0000% |
| base_50 | 0.50 | 0.80 | 0.05 | 4000 / 250 | 94.1176% |
| shifted_fpr | 0.10 | 0.80 | 0.20 | 800 / 1800 | 30.7692% |
| lower_fpr | 0.01 | 0.80 | 0.01 | 80 / 99 | 44.6927% |

前三行仅假定base rate变化、条件recall/FPR不变；第四行说明FPR漂移时原结论会怎样改变，第五行说明低base rate下即使FPR降至1%也不自动变成身份确定性。以上均为假设敏感性分析，不是真实检测器性能、群体规律或处分阈值建议。不要用刻意均衡的benchmark比例、检测器的标记比例或受检者是否申诉来替代目标base rate；如有抽样偏倚，还要恢复相应目标分布，不能直接套平衡样本precision。

### 3. 评估时先固定标签与分母

先写清检测版本、score含义、阈值/拒判带、文本单位（整篇或片段）、语言、体裁、长度、时间和AI辅助范围。切分训练/阈值开发/校准/最终评估集时，按作者、任务或原始文本family分组；同一文章的片段、翻译和改写不能一份调参、一份报成绩。阈值在开发集选择后冻结，最终集不能反复试到最好；评估之外还需监测模型和人群变化。

对每个计划样本保留来源标签证据、文本版本hash、是否符合输入要求、实际检测状态和分数。混淆矩阵只对标签可判定且得到约定二元决定的样本计TP/FP/FN/TN；同时公开标签覆盖、决定覆盖、拒判、错误、未支持与缺失的原分母。未知不自动等于人工，mixed不强塞进二分类，检测失败不自动变成低分；只报成功子集会隐藏选择偏差。

按语言、熟练度情境、长度、任务和改写条件报告分群FPR/recall/precision及数量，小样本的不确定性另列。群体应来自有权限、合适的研究信息，不能从文风反推出某人的语言背景。Liang等作者摘要报告其研究中的非母语英文写作样本被误判，以及分数对改写的敏感性；本题未读取原始写作样本或复现实验，也不把该结果当中文、所有群体或2026年所有工具的误报率。[1]

改写、翻译、新模型和专业术语都可能改变分布，不能假定原r/f仍成立。多个检测器可能共享特征与训练偏差，“三个都报高分”也不是三份独立身份凭据。最终要回答的是在当前用途下、可接受的误报和覆盖代价内还能否筛查，而不是追求一个脱离人群的总准确率。

### 4. 原创合成记录：验证计算，不验证检测能力

本轮另建 **24个计划文本版本、20个family、23条预设结果记录**，其中21条有分数，2条只有错误/未支持状态，另1条记录缺失。文本全部由本题作者原创合成；`human/ai/mixed/unknown`和`en_native_scenario/en_l2_scenario/zh_scenario/rewrite_scenario`都是虚构场景标签，**没有真人写作样本，也没有实际检测器**。它们只用于核对计算和记录绑定，不能将标签为human的合成文字说成真实人类写作。

mock-detector-v1的分数为预设十进制字符串；示意规则是 `score>=0.60`标记、`score<0.40`低于阈值，中间拒判。该分段未经真实校准，不代表推荐产品阈值。样本及实际record.context分开保存，递归校验完整字段、类型与取值，绑定文本hash、版本、语言和嵌套设置；整数1不能被布尔true或浮点1.0冒充。检查所有实际记录后才汇总；重复、越界、漂移及错误状态携带分数均拒绝，不静默删样本。hash/类型检查只证明合成记录一致，不认证作者或实际服务执行。

24个版本中，设定AI8、人工8、mixed4、unknown4；产生10个标记、9个低于阈值、2个拒判，另有缺失/错误/未支持各1。二分类标签已知16个，其中一个AI类缺少分数，因此决定覆盖 **15/16**。已知且决定明确的矩阵为 **TP=4、FP=3、FN=3、TN=5**：precision **4/7≈57.14%**，条件recall **4/7**，条件FPR **3/8**。

原计划8个已知AI类中确认标记4个，标记产出为 **4/8=50%**，须与缺失状态一起看，不能把未观测的那一项补成FN来伪造完整检测recall。10个总标记里还有1个unknown和2个mixed，不能把它们当3个误报或3个真阳性；总体标记率10/24也不是precision。

| 虚构分组 | TP / FP / FN / TN | 已知明确决定上的FPR | 已知明确决定上的precision |
| --- | --- | --- | --- |
| en_native_scenario | 1 / 1 / 1 / 1 | 1/2 | 1/2 |
| en_l2_scenario | 2 / 2 / 0 / 0 | 2/2 | 2/4 |
| zh_scenario | 1 / 0 / 0 / 2 | 0/2 | 1/1；另有1个AI分数缺失 |
| rewrite_scenario | 0 / 0 / 2 / 2 | 0/2 | null（没有已知标签的正标记） |

汇总FPR=3/8会掩盖这些预设差异；每组只有2个“人工”场景，不能由此推断任何真实人群风险或统计显著性。rewrite组仍有一个mixed被标记，不会被用于把该组precision从null凑成0或1。同family两条AI场景记录的分数可预设为0.90→0.20，只说明检测分与设定来源标签不等同；本轮没有执行或验证改写攻击。24个文本版本也不是24名独立作者。

脚本另外验证空评估集、全部未知、全部拒判、全缺失、无人工类别及无标记的零分母；显示null而非“100%准确”。失败/拒判时某个保守标记产出为0，不代表检测器有效，需要同时看覆盖。上述24条记录与前面的N=10000期望计算是两组独立演示，不能拿平衡合成标签估计真实base rate。

### 5. 两种使用方式与申诉边界

**低风险筛查＋人工复核**适用于已经验证过当前语言、体裁、阈值和误报成本，且标记只用于安排复核的场景。优点是减少初筛工作；代价是拒判、漏报与人工负担，还需持续维护分群验证。输出应写“该版本工具在此输入上的筛查标记，需要上下文核对”，不能写“此人由AI代写”。不适用于未验证语言/短文本，也不适用于自动拒稿、扣分、解雇或确定归因。

**过程证据优先、不依赖检测分定案**更适合教育、招聘等高后果判断：先明确允许哪些辅助、评价什么能力，再按需核对大纲、草稿、版本差异、引用依据及对方自愿提供的说明。优点是更贴近任务过程和规则；代价是人力、记录缺失与证据可伪造风险。不能因为没有编辑历史就认定违规，也不能要求人人持续录屏或交出无关私人聊天。

可设计“说明疑点及依据 → 暂缓不利决定 → 当事人补充或更正 → 不依赖原检测结论的复核 → 记录理由与救济结果”的申诉流程。应保留对方可理解的检测版本、输入范围、错误可能性与申诉渠道，限制证据用途和访问；给不同语言能力、残障或沟通方式合理表达机会。口头解释紧张、表达不流畅并不证明没写过；草稿、时间戳、录屏也不是不可伪造的认证。必要证据不足时保持未决，不用检测分替代缺失证据。这里是设计建议，本轮没有开展真实申诉或处分。

### 6. 实际验证与限制

本轮标准库合成验证 **50项通过**，覆盖Bayes期望计数、base rate/FPR敏感性、零分母、unknown/mixed分离、拒判/缺失覆盖、分群、阈值端点、全文本hash/嵌套context类型、family划分及score不能确定身份。三份教学错误分别把recall当precision、未知当人工真值、标记当作者身份；同一三项探针各得到真实exit1/1failure/0errors，正确版exit0/3pass。这些是主动注错，不是线上测量或独立review结论。

便携副本复跑50项、全部计算和教学探针，3直接+4嵌套子进程均收集；result/table bytes一致，输入、代码和测试未变，专属临时目录清理，原fixture与原始输出保留。没有读取用户文章、学生作业或凭据，没有上传真实文本；真实检测器、真人写作研究、真实校准、申诉/处分、浏览器均 **not_run**，`authorship_effect=null`、`production_approved=false`。

常见误区是“分数就是身份概率”“FPR=5%所以标记者95%可信”“低分证明没用AI”“未知全算人工”“总体准确率高就不存在群体偏差”“三份检测报告或一段录屏足以定案”。对应纠正是先明确事件与分母，再核对适用分布、未知覆盖和独立过程证据，保留申诉与未决状态。

## 延伸 / 追问

- **某检测器在50/50测试集上precision很高，部署时AI文本只占1%，还能沿用吗？** 不能直接沿用。需要匹配部署分布估计r/f和base rate，按条件概率重算，并报告不确定性；如果只是label shift且r/f稳定，才可按公式换算，现实漂移可能同时改变r/f。
- **改写后分数降低，能否证明原文是AI、改稿是人写？** 都不能。分数变化是工具输出变化；应按预先定义的来源标签和修改范围核对，mixed/unknown保留。对攻击鲁棒性的实验也只支持相应模型、文本和修改条件。
- **被标记者拿不出草稿怎么办？** 缺少记录不等于有罪。允许替代说明和与任务相关的证据，独立复核时考虑保存习惯、可访问性和沟通限制；证据仍不足就记录未决，不能让单一分数承担身份或违规证明。
