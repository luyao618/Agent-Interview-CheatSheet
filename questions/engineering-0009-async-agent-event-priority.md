## 问题

异步 Agent 会有一个事件/任务队列（用户消息、定时触发、工具回调、子 Agent 结果…），需要决定先处理哪个。这个优先级应该由规则引擎判断，还是交给 LLM 判断？

## 答案

> 🤖 AI 答案 · 模型：Claude-Opus-4.8 · 回答 2026-08-06

**先破二选一：不是规则 vs LLM，而是分层。** 优先级里既有**确定性、要快、要可预测**的部分（SLA、类型、显式紧急标记），也有**需要理解语义**的部分（这条用户消息是随口一问还是线上事故）。规则引擎快（微秒级）、可解释、零成本但读不懂语义；LLM 懂语义但慢（数百 ms～秒）、贵、有不确定性。**让规则做主干、LLM 只在规则拿不准时补语义分**，是稳妥解。

```
入队事件
   │
   ▼ ① 规则层（快·确定）
   ├─ 硬约束：SLA/deadline、显式 urgent、类型权重
   │        （工具回调>定时任务、付费用户>免费）
   │  能定则定 ──────────────────────────► 优先级分
   ▼ 规则判不准（如"自由文本消息有多急"）
   ② LLM 分类器（懂语义·慢·贵）
   ├─ 轻量模型给紧急度打分，带缓存/批处理/超时兜底
   ▼
   最终分 = w1·规则分 + w2·LLM语义分
   ── 老化(aging)防饥饿 ──► 出队执行
```

**为什么这样分：**

1. **规则做主干**：绝大多数事件靠类型、来源、SLA、显式标记就能定序——快、可预测、可测试、可审计。**别为能规则化的判断付 LLM 的延迟与成本**，尤其调度本身在热路径上，每个事件都过一次 LLM 不可接受。

2. **LLM 只补语义空缺**：真正需要"读懂内容"才能判急缓的少数事件（自由文本消息、模糊工单）才交 LLM 打分，并且用**小模型 + 结果缓存 + 批量评分 + 超时兜底**降本；LLM 挂了/超时就退回规则默认分，不阻塞队列。

3. **LLM 的不确定性要隔离**：它只输出一个**建议分**参与加权，不直接掌控出队；避免"模型抽风把 P0 压到队尾"。高风险场景对 LLM 判分设**护栏**（如再高也不能越过硬 SLA）。

**必须解决队列饥饿：** 无论谁打分，纯优先级队列都会让低优任务永远排不上。加**老化（aging）**——等待越久优先级递增，或给低优保留固定处理配额/独立 worker，保证最终都被处理。

**一句话：** 规则做确定性主干（快、可解释、扛住热路径），LLM 只在"必须懂语义"处出一个可兜底、可缓存、带护栏的建议分，二者加权定序，再用老化防饥饿——**别让每个事件都等一次模型，也别让模型独断出队**。

## 延伸 / 追问

**追问：什么信号提示"该从纯规则升级到引入 LLM 打分"？反过来，什么时候不该上 LLM？**

看**误判是否集中在"规则读不懂语义"上**。该上 LLM 的信号：① 大量事件是**自由文本**（用户消息、工单描述），紧急度藏在语义里，规则只能靠关键词硬匹配、误伤多；② 线上出现"重要请求被排到低优、次要请求抢占"的实际投诉，且根因是分类维度不够而非阈值没调好；③ 类目和紧急模式**频繁演变**，维护规则的成本高于跑一个分类器。不该上 LLM 的场景：① 事件类型少且边界清晰（就那几种回调/定时），规则足以覆盖；② 调度在**极低延迟热路径**、量极大，每事件过 LLM 的延迟/成本不可承受——此时宁可离线用 LLM 优化规则、而非在线判分；③ 需要**强可解释/可审计**（金融、合规），LLM 的不确定性不可接受。折中：先用规则跑、离线拿 LLM 分析误判样本反哺规则，只有当"语义类误判"持续且规则化成本过高时，才把 LLM 引到在线、且限定在补分而非独断。
