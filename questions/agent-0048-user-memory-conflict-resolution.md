## 问题

跨会话维护用户记忆时，新写入与已有记忆冲突（例如"用户住在北京"↔"用户住在上海"、"喜欢咖啡"↔"戒咖啡了"）。Agent 应该直接覆盖、合并保留，还是追问用户确认？依据什么来决策？

## 答案

> 🤖 AI 答案 · 模型：Claude-Opus-4.8 · 日期 2026-08-06

**先分清冲突的两种性质，别一刀切。** 「住在北京→住在上海」多半是**事实变更**（用户搬家了，旧值已过期）；「工作日 vs 周末的偏好不同」是**语境并存**（两条都真，只是作用域不同）；「刚说 A 又说非 A」可能是**口误/噪声**。覆盖、合并、追问不是三选一的偏好，而是**按冲突类型 + 置信度 + 代价**路由出来的结果。

**决策要素（每条记忆都带的元数据）：** 时间戳（谁更新）、置信度（显式声明>顺带提及>推断）、来源（用户亲述>工具观测>模型猜测）、作用域（全局/情境）、可变性（稳定事实 vs 易变偏好）。

```
新记忆 vs 旧记忆冲突
        │
        ▼ 是同一维度的互斥事实吗？
  ┌─────┴─────────────────────────┐
  否（不同作用域/维度）            是（真互斥）
  → 合并：并存，标注各自 scope     → 看置信度与代价
                              ┌───┴────────────────┐
                          高置信 + 低风险         低置信 或 高风险
                          （用户明确改口，        （矛盾来源模糊，或
                            如"我搬去上海了"）      改的是重要/敏感项）
                          → 覆盖（软覆盖：          → 追问确认，
                            旧值降级留历史，          用户拍板后再落库
                            非物理删）
```

**三条落地原则：**

1. **默认不硬删，软覆盖 + 留痕。** 覆盖时把旧值标记为 `superseded` 并保留历史（带时间戳），而非物理删除——既支持「其实我没搬，说错了」的回滚，也便于审计。最新且高置信的作为**当前生效值**。

2. **能合并就别覆盖。** 冲突常是「作用域不同」的假冲突：给记忆挂 scope/条件（工作日 vs 周末、项目 A vs B），两条并存、按情境取用，比粗暴覆盖更保真。

3. **高代价/低置信才追问，且问得省事。** 追问有打扰成本，只在**改动重要或敏感项、且置信度不足**时触发；问法给「二选一 + 各自后果」而非开放式，降低用户负担。低风险的易变偏好可先按最新值走、留可纠正入口。

**一句话：按冲突类型路由——假冲突合并、真变更软覆盖留痕、重要又拿不准才追问**，用时间戳/置信度/来源/作用域四元数据驱动，而不是无脑「新的盖旧的」。

## 延伸 / 追问

**追问：用户要求"忘掉某条记忆"（隐私删除）时，和上面的"软覆盖留历史"会不会冲突？怎么处理？**

会，且必须让**隐私删除优先于留痕**。两者目的不同：软覆盖留历史是为了纠错与审计，隐私删除是用户对自己数据的支配权（GDPR「被遗忘权」）。当用户显式要求删除，应做**真删除（hard delete）**——不仅清当前值，连同 `superseded` 的历史副本、以及派生的嵌入/索引/缓存一起清，并给可核验的删除确认；不能用「只是标记 superseded」来搪塞，否则数据仍在。工程上区分两类失效：**冲突导致的过期**用软覆盖保留可回溯历史；**用户主动的隐私删除**走硬删除并留一条「已按请求删除」的极简审计（不含被删内容本身）。此外，敏感类目（健康、宗教、政治等）默认更短的保留期与更严的作用域，从设计上减少「记太多、留太久」的风险。
