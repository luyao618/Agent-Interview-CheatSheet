先证明内容在哪个回答中被怎样使用，再讨论是否带来可观测的业务价值。 SEO 通常关注搜索中的可发现性、展示、排序及有价值的访问；GEO（Generative Engine Optimization）额外关注内容是否进入生成式回答、出处是否可见、引文是否准确支持结论，以及用户是否因此采取有价值的行动。两者共享内容质量和可访问性基础，搜索也可能同时展示链接与生成式回答，不能把它们划成互斥渠道。

product-0003 讨论通用业务指标，rag-0038 讨论检索信息质量；本题聚焦搜索分发后的可观测证据。一次爬虫请求、一个引用链接、一笔转化分别回答不同问题，不能用同一个“曝光量”替代。

1. 先拆测量链，别把不同单位硬接成漏斗

层次与单位 可用证据与口径 不能由此推出
抓取：页面 × 引擎 × 时间窗 经核验的爬虫身份、请求时间、响应状态、正文版本；抓取成功页数/计划检查页数，错误和未知另列 User-Agent 可伪装；训练抓取与搜索检索用途不同。请求增加不证明索引、引用或真人访问增加
索引：同一页面观察单元 引擎提供的诊断、canonical 与最近抓取状态；确认索引/计划检查，no 与 unknown 分开 查不到观测不等于未索引；site: 结果不能充当完整库存。旧索引可能存在而本窗口没观测到抓取
引用：问题 × 引擎/模式 × 日期 × 抽样次序 保存完整回答、链接和实际运行上下文；带目标站出处的回答数/全部计划槽位 品牌提及不是出处链接；已索引不保证被挑中。回答可能引用转载或旧快照
支持：原子结论 × 所引来源版本 逐项检查可访问、相关、支持/矛盾/不足，匹配产品、地区、有效期及限定条件 链接能打开或主题相关不代表支持结论；模型自评与检索相似分不代替证据核验
转化：可观测访问会话/合格行动 明确 referral、去重规则、跟踪覆盖及成熟观察窗，单列未知来源与不可观测行为 引用不等于点击，点击不等于收益；观察到的归因不等于新增因果收益

这是一条排障顺序，不是每层分子都能除以上一层分子的数学漏斗。页面、回答、引用对和会话的分母不同；跨层连接必须有可解释的 ID、时间与版本证据。不能把某次爬取归给所有后续回答，也不能假设所有产品都使用同一搜索索引。

Google 一手文档限定：页面要成为 AI Overviews/AI Mode 的 supporting link，须具备索引和 snippet 展示资格；满足条件仍不保证抓取、索引或展示。该限制不能外推为其他引擎的内部架构。[1][2]

2. 内容怎么做，优先级怎么选

基础修复与小型证据集适合资源有限、抓取或正文可读性已有问题的站点：先清理可访问性、canonical、内部链接与内容更新流程，再围绕真实任务写少量能独立理解的答案段。每段说明对象、条件、单位、时点、例外及出处，把摘要与可核对证据连起来。代价是覆盖扩张慢；不适合拿少数精选问题代表整个需求市场。

分层内容组合与持续抽样适合基础稳定、任务类型较多的产品：预先按品牌/非品牌、事实/比较/行动意图、语言/地区分层，维护问题集与版本，抽样核对回答和转化。代价是标注、刷新与失败诊断成本；在没有可靠版本和分母时不宜扩大成几千条“自动引用榜”。两种方案都先保证内容对人准确有用，不为了被引用捏造统计、堆砌品牌、隐藏限定条件或给爬虫一套不同事实。

llms.txt 可以作为供适配客户端使用的内容导览，但不是收录合同。本轮读取的 Jeremy Howard 提案为 v2，2026-08-10 修改；Google 文档说 AI features 无需特殊 AI 文本文件或 schema，其 2026-06-15 更新记录还明确 llms.txt 不影响 Google Search 的可见性或排名。不要把这种单引擎说明外推到所有客户端。[1][3][4]

FAQ schema 也不保证收录或引用。尤其要更新时点：Google 官方 2026-05-08 条目说明 FAQ rich result 从 2026-05-07 起不再展示，2026-06-15 移除了相关文档；截至本题 2026-09-17 核对，不应再把旧的 FAQ 富结果测试当 Google 引用验收。此变化不等于 schema.org 类型消失，也不表示其他引擎行为相同。结构化描述仍应与可见事实一致。[1][3]

3. 把问题、引擎、版本和抽样协议冻结在看结果之前

先列问题原文与 hash、分层、目标站 canonical 域名、语言/地区、时区、采样窗口和重复次数，再登记引擎、产品模式、实际入口（UI/API）、公开模型或版本标识、联网设置和会话条件。产品没有公开底层版本时写 unknown，保存界面/接口可见标识和日期，不编造模型名；UI 与 API 结果分开。固定新会话或明确个性化条件，记录执行次序，避免总让一个引擎先跑。

计划定义与实际记录要分别校验。接收每条记录时，对完整 record.context 与冻结 slot 递归比较字段、JSON值类型和取值；本例也严格区分整数 1、浮点 1.0 与布尔 true。对象键顺序不影响绑定，数组顺序、嵌套字段及缺失/额外字段会影响。成功、失败、重试后成功和明确未运行的记录均先过此检查；不匹配就拒绝这批输入，不能静默丢掉坏记录后缩小分母。相同检查用于重复事件ID的完整载荷，避免类型漂移被当作相同重传。它只证明记录与计划一致，不认证实际引擎运行或提供并发CAS。

每个计划槽位都有 ID，超时、限流、拒绝、没有触发生成式回答、调度未执行及记录遗失分别保留。重试预算提前约定，保存每次尝试，按固定规则取最终结果；不能刷到一次好答案就算成功或把重试当独立新样本。主报“已确认引用/全部计划槽位”，同时报完成率、成功回答内引用率及每个问题的重复稳定性。失去观测的槽位是未知，不把主报的保守分子解释成已经证明“未引用”。

周际比较保留同一核心问题集、窗口和条件；新探索问题另列。若意图分布确实改变，公开新旧权重与重叠子集，不在看到结果后换题。等权题目平均只是该测试集的描述；只有预先定义目标分布和合法抽样概率时才做相应加权。一次问题的多次生成应视为相关观测，不能当多名独立用户计算显著性；选择优化方案的开发集与最终报告集应隔离。

Google 说明 AI Mode 和 AI Overviews 的模型、技术及链接可能不同，生成式功能也不一定触发。其 Search Console 数据归入总体 Web 搜索流量；只有该报表不足以还原每条回答的引用和支持性，需分别获取有权限的观测，保留无法细分的限制。[1]

4. 原创合成例：覆盖相同，证据质量可以不同

来源注册表保存原创字段、版本内容 hash 和有效区间。旧试用政策为7天、有效至9月15日之前；新政策从9月15日起为14天。规格为24个月保修、2个接口；远程同步不能离线。另有不同产品页和不可访问来源。逻辑日期只用于计算，没有等待这些日期或让真人查询。

每个槽位的完整计划与记录context分别保存在原始合成输入中。类型敏感校验发生在汇总和归因之前；以下数值仅来自通过绑定的原始合法记录，记录确实缺失的槽位仍保留原计划分母。

5. 归因要保留可观测范围

本例另设8个合成会话：6个声明AI来源、1个来源未知、1个bot；每会话仅一个入口，不模拟多触点竞争。逻辑截止为 2026-09-24 12:00 UTC，转化窗为入口后的7×24小时。6个AI来源会话里，1个窗口未成熟、1个跟踪不完整；其余4个可判定会话有2个转化，得到 2/4=50% 的“成熟且完整观测的AI来源会话转化率”。不能写成所有AI曝光的转化率，未成熟与跟踪未知均不是已证明没转化。

其中3个会话带有合成回答关联，2个转化，即2/3；另1个仅知道来源，不能分配到具体回答。来源未知的会话也有1次转化，单独保留，不能顺手算给AI；重复传输的同一事件去重，多次转化也按会话计一次。跟踪不完整但已看到的正向事件可另记已知下限，不能抹去，也不能用它补造完整观察。点击早于回答、失败/无引用回答获得出处点击、冲突事件 ID 均拒绝。

真实方案还要预先声明多触点归因模型、有效行动/退款口径、同意与数据最小化要求。referrer 缺失、跨设备、应用内浏览器、零点击阅读和后续品牌搜索会让链路断裂；既不能强行拼接用户身份，也不能把未观测效应都设为零。代码中的确定关联只是合成 ID 检查，不能证明真实跨系统归因。

要验证增量收益，可设计随机分配或分批发布的对照，保持内容条件与测量方式可比，预注册主指标、观察窗、停止条件及准确率/投诉/品牌误引护栏；搜索环境变化、页面互相影响与同期活动可能破坏识别。若只能做前后观测，报告相关变化与竞争解释。本轮未执行任何实验，business_gain=null，不能从上述预设数字推导优化使收益上升。

6. 验收记录与误区

本轮本地执行标准库脚本：50项测试通过，覆盖计划完整性、重试/缺失、条件漂移、引用去重、过期/矛盾/不足/无关/未知、类型边界、页面观测缺失、归因时序、窗口成熟度、跟踪未知与重复事件。三份故意错误的教学版本分别把失败剔出分母、相关当支持、未知来源转化算给AI；同一三项探针各得到真实 exit1/1failure/0errors，正确版 exit0/3pass。这是教学注错，不是线上事故或独立review结论。

原50项虽全绿，却漏测实际context.repeat的类型绑定。 独立review发现旧版只严格检查计划整数1，实际记录用普通字典相等，错误接受 true 和 1.0；这是同一P2的两种输入，反例指标与原样本相同，不称已造成指标膨胀或业务损失。原样三项回归保留旧版真实 exit1 / 3tests / 2failures / 0errors，修复版 exit0 / 3pass，测试hash、原输入及两版反例输入不变。另22项验证嵌套类型、键/数组顺序、缺失/额外字段、失败/未运行/重试路径、重复事件绑定和汇总前拒绝；原50项与16槽位计算全量复跑，原结果/table bytes不变。

便携目录复跑50项、完整计算和教学探针，3个直接子进程与4个嵌套子进程均已收集；结果/表格 bytes 一致，原创输入与源码未变，专属临时目录已清理，原fixture和证据保留。时间与环境、输入/计划/源码 hash、原始输出随 YAO-419 验证包交付。真人行为、真实生成式引擎、分析日志、浏览器、因果实验均 not_run；没有修改真实站点、schema、robots 或发布流程，production_approved=false。

修订便携包另复跑原50项、完整计算、教学探针、reviewer三项及新增22项，5个直接子进程和5个嵌套子进程均已收集；合法结果、表格和修复版回归记录bytes一致，运行期间源码/输入/测试未变，临时目录清理。本轮修复保留独立review于2026-09-17取得的Google当前HTML及其与历史manifest的三份hash差异；未改manifest伪造旧网页重现。本文所引规则在reviewer当前正文中另行核对，本修复轮未再次联网获取来源，也不把动态HTML差异断言为仅模板变化。

常见误区是“llms.txt/FAQ schema 一加就收录”“bot增多就是引用提升”“链接相关就是结论正确”“只看成功回答就能比较引擎”“品牌提及或直接访问都归AI”。对应修正是查当前产品规则、分层保存证据、逐项验证支持、保留计划分母，以及把未知归因和因果限制写在结果旁。

索引确认数没变，引用覆盖下降，先查什么？

追答

先看完成率和观测缺失，再对齐原问题/引擎模式/日期/地区，核对是否触发生成式回答、链接 canonical 与源快照，检查内容新鲜度、竞品或引擎选择变化。索引没变只说明一个层次，不能据此把下降归咎于内容不够“AI友好”。

按预先约定的准确率和风险护栏处置；抽查哪些结论被过期、断章或不相关来源支撑，优先修正文档限定条件和版本管理。若高风险误引增加，先停该类扩张，覆盖收益不足以抵消误导。
