先分清系统什么时候做完、用户什么时候拿到能用的东西、以及用户觉得等了多久。 真实进度可以减少“是否卡住”的不确定性，流式可以提前交付部分价值；这些不自动减少计算耗时，也不能据此推断主观感受或完成率改善。应从有来源的事件生成状态，再用独立实验检验体验，不能编“正在深度思考”、虚构百分比或故意多等几秒来表现努力。

一般失败/恢复体验见 product-0004，质量/成本/业务指标见 product-0003。本题聚焦反馈的因果验证和真实性，不把“加一个进度条”本身当作体验已验收。

1. 把延迟拆成可核对的观测点

指标 起止与含义 不能替代什么
TTFT / 首内容到达 必须说明测量层和事件。本例客户端代理为请求发出→首个非空 content_delta 到达；ack、heartbeat、空片段不计 不是网络首字节TTFB、模型内部首Token时点或用户已看见结果
首次可见内容 请求发出→展示层首次提交真实内容片段 一个标题或半句可以很早出现，但未必可用
首个可用结果 请求发出→用户可见的、满足预定义最低验收单元的结果 首Token、阶段消息和“快好了”都不能自动算可用
完整任务时长 请求发出→完整结果通过验收并向用户交付 服务端done、HTTP成功或局部结果均不等于用户目标完成
主观等待 用户对等待长短/可接受程度的报告，例如固定时点的同一量表 不能从动画帧数、TTFT或客观12秒直接计算出来

GenAI-Perf 固定文档将其 TTFT 定义为请求发出至首个响应接收，将 request latency 定义为至最终响应接收；它描述工具的测量点，不是所有应用的共同口径。本文是首内容片段代理，不测真实模型Token；非流式协议、首片段缺测或用户已退出时应标缺失/不适用，不能填0或把确认包偷算成Token。

同一端的时长应使用同一时间原点的单调时钟。W3C High Resolution Time 的固定编辑稿说明 wall clock可能调整，而monotonic clock适于时长测量，但其单调性质不能跨任意独立执行直接比较。服务端生成、网络到达、客户端渲染、后台标签页节流要分开记录，用关联ID对齐；不能直接用两台机器的时间戳相减，也不能把处理回调当作像素已呈现。

“可用”须在试验前定义。本例任务是返回合成列表 [2,3,4] 的数量与总和：校验过的数量3是可读的最小单元，完整任务仍要求数量3与总和9都交付。若真实任务只需要数量，应重新定义目标，而不是坚持让用户等齐无关内容。高风险判断或可能被后文推翻的内容，不宜仅因流式片段出现就允许行动。

2. 同一条12秒事件源，三种展示策略

以下是原创合成事件与虚拟毫秒时间轴，不是真实检索/模型运行，更不是真人行为。三臂共享相同事件、结果与最终时点；“事实”指fixture中可核对的事件及小数据校验，不构成后端真实性认证。程序不sleep、不制造实际12秒等待。

共同时间轴：0秒提交；0.2秒收到受理事件；1秒开始检索；3.5秒检索完成并开始生成；4秒首内容片段“条目数量：”；6秒数量3的单元通过校验；9秒生成阶段结束、开始最终核对；12秒数量3/总和9通过完整验收。

  • 静默臂：共同提交确认后，不显示中间阶段或内容，最终结果就绪即显示。它是只交付完整答案的比较策略，不延后已经完成的最终结果；取消和错误通知仍保留。
  • 真实阶段臂：仅在来源事件到达后显示“检索样例资料中”“生成结果中”“最终核对中”等状态；6秒可报告首单元已校验，但不展示答案片段。阶段顺序和完成事件配对，不能按定时器猜当前正在做什么。
  • 流式臂：显示真实内容片段，6秒交付已校验单元，12秒交付完整结果；中间仍标为未完成。本对照不额外叠加阶段故事，便于解释处理差异。真实应用还需评估阅读打断、跳动和无障碍播报，不按每个Token疯狂宣布状态。
展示臂 客户端TTFT代理 首次可见内容 首个可用结果 完整交付 主观等待
静默 4秒 12秒 12秒 12秒 not_run
真实阶段 4秒 12秒 12秒 12秒 not_run
流式 4秒 4秒 6秒 12秒 not_run

流式在本契约中把首个可用单元提前了6秒，完整交付仍是12秒，主观等待未知。阶段臂0.2秒已有真实状态，但没有提前可用答案。这些是展示函数的逻辑结果，不是用户更满意或更愿意完成的因果证据。

三阶段不代表每阶段占三分之一工作或剩余时间，故本例始终不给数值百分比。只有工作单位、总量和分母范围可核实时，才考虑“已处理x/y项”，并说明它不一定是剩余时间比例。WAI-ARIA 1.2 对不确定进度建议省略 aria-valuenow；这支持如实表达未知，不支持填一个看起来合理的50%。本例只验证抽象展示状态，未构建DOM或测试屏幕阅读器。

对照还必须保证不额外拖延：把同一源的最终完成事件从12秒改到10秒，三臂都在10秒交付，不能为了展示满三个阶段而等回12秒。这里的“同总时长”是回放控制；线上不要人为补sleep，也不要事后只挑恰好12秒完成的样本来消除差异，那会引入处理后筛选。

3. 选择反馈方式的取舍

真实阶段反馈适合长任务且阶段事件可观测的系统，能说明发生了什么；代价是维护事件语义、缺失/重试/并行阶段与用户文案的对应关系，不能用于没有进度来源却想讲故事的场景。静默完整交付实现简单、避免未验证内容干扰，适合很短或必须整体核对的结果；长等待时需要至少保留确认、取消与超时恢复。

流式适合分段内容本身就有价值、能安全消费的任务，代价是片段不稳定、用户阅读负担和后续失败处理。涉及付款、危险操作或需要全文一致性校验时，应把可预览片段和可执行结论分开；流出很多字不等于任务快。展示状态应来自可信运行事件，模型输出的“我已检索”不能直接充当执行事实，更不应展示隐藏推理来证明努力。

Buell 与 Norton 的2011年论文出版摘要报告了在线旅行和约会模拟服务中的5项实验，讨论过程透明度、感知努力与服务价值，有比较更长等待与即时结果的情形。本文只核对出版摘要/元数据，未读取全文或复现实验；这些场景与终点不是本AI产品的完成率或主观等待。不照搬制造延迟/努力信号的处理，不把心理学效应当作本产品的保底收益。

4. 分群A/B/n：检验体验，同时守住完成率

真实试验先预注册假设、目标人群、指标、停止规则和最小有意义效应，再上线分流；本轮没有开展此实验。可用三臂A/B/n，预先约定“阶段对静默”“流式对静默”两项主比较；不要看完结果再选择有利对照。

  • 分配与分群：按用户固定分臂，主分析取每名用户的首个合格任务，避免同一人反复切换学习或污染；重复任务作次要分析并按用户聚类。按分配前确定的新/回访用户、任务类型/预计复杂度、设备等分层；不按实际耗时、是否留到最后或满意度事后分群。
  • 控制与诊断：模型、工具、质量门槛、调度与缓存策略等保持一致并记录，检查分配比例、曝光、漏记及样本比例异常。真实延迟分布也作为护栏；显示变化若增加主线程工作、重试或资源争用，就不能再称仅改变感知。不要通过延迟最快组来强行匹配总时长。
  • 主观终点：例如预先选定“感觉等待很漫长”的同一量表，在一致时点向各臂邀请自愿反馈，并记录响应率。未答卷不能记0；只问完成者会产生选择偏差，退出者往往不可观测。主观效应要明确可识别的人群、缺失假设和敏感性分析，不能仅比较留下来的人。
  • 完成率护栏：预先定义完整可用结果及观察窗（例如24小时内的首任务，例值须按业务校准）。分母保留所有随机分配且事前合格的分析单位；失败、退出、超时和未决结果分别登记。重连/跨设备回访按原分配和任务关联，不能把一次关闭页面直接当作永久失败，也不能因未曝光就事后删除。
  • 统计与停止：例如要求完成率差下界高于−2个百分点，并同时守住严重错误、退出、质量、成本及关键分群护栏。阈值是示例，需按风险预定；两项比较预先控制多重检验，如总α=0.05、每项α=0.025。样本量由真实基线、功效与最小效应确定；固定观察窗或合规的序贯方案，避免每天窥看后随意停。发现安全问题先停止，不能等主观评分来抵消。

5. 失败、退出和未知不能伪装成完成

9秒发生失败时，即使流式6秒已有可用数量，完整完成时长仍为空；失败时刻只记time-to-failure。已校验快照与未校验预览必须分开保存：后续增量不能因为之前有单元通过校验就得到背书。失败只恢复当时已校验、已展示的快照，没有快照则清空；取消请求与超时也清除未校验预览，静默/阶段臂不在失败后补发原本隐藏的部分内容。完整成功时再用通过全部验收的结果替换预览。

5秒退出时，客户端已见首片段却没拿到6秒的可用单元；后台源仍可在12秒结束，不代表用户完成，也不能把5秒当更快完成。3秒退出后出现的源内容不算客户端已观察TTFT。

取消只显示已经确认的事实，例如“已请求取消，服务端是否停止尚未确认”，不能因为前端停止更新就宣布服务取消成功。20秒watchdog只说明截至期限未确认完成，不能补造100%或成功时长。已终止的展示序列不再接收迟到内容；真实服务的取消/清理与重连需要另测。

在统计中，未决样本的下界为已确认完成/全部分配，上界可暂按（已确认完成+未决）/全部分配报告；这不是把未决一律判失败，也不是把它们删除。只有成功样本的平均时长可能因慢用户退出而下降，必须同时看完成/失败/退出分布、完整观察窗与删失假设，不能据此宣称整体更快。

6. 本题实际验证的范围

原创Python回放使用同一虚拟单调时钟，9种场景×3臂共27份投影，覆盖成功、首内容前/可用单元后失败、三个退出时点、取消请求、超时与更早最终完成；原29项测试检查时间/阶段顺序、相同前缀不泄漏未来、无数值假进度、片段与可用/完整分离、迟到更新、重复/冲突事件、真实分母和未知结果。原29项当时全绿，但漏测了“校验后继续流入未校验内容，再失败”的合法交错。 事件数量上界64、虚拟时间上界30,000ms，程序没有sleep或真实服务调用。

独立review补入的真实反例：6秒数量3通过校验，6.5秒收到预览“；合计：999”，9秒失败。旧版只保存 validated_unit 布尔值，把“条目数量：3；合计：999”一并声明为已校验，虽然 completed_ms 仍为null；缺陷是未校验内容被背书，不是失败算完成。原样三项回归在旧版真实exit1 / 1 failure / 0 errors，修复版exit0 / 3pass。修复使用独立的已校验内容快照与预览缓冲，终止时只恢复快照；另加9项相邻回归覆盖取消/超时、多段尾部、重新校验及提前成功。原29项、27份投影的时间/分群结果和原教学反例均保留复跑，不能把旧漏测改写成从未发生。

同一组三条断言对三份教学错误副本分别真实exit1 / 1 failure / 0 errors：虚构50%进度、把退出时间写成完成、只用成功者作分母；修正版exit0 / 3pass。便携临时副本完整复跑，输入不变且资源回收。它们证明给定数据下的算术/展示契约能检出这些错误，不证明真实界面、并发协议、身份认证、真人感受或因果收益。

主观等待为null，human_experiment=not_run、browser_rendering=not_run、real_service=not_run、production_approved=false。没有读取用户会话/凭据、开展用户研究、修改业务UI或服务；题库GFM文本与表格验证也不等于页面图像布局验收。

常见误区

  • “心理学证明多等一会儿更可信。” 特定研究的任务、样本与价值评价不能自动外推到AI；不以此支持人为拖延或虚假努力。
  • “阶段条33%就是还剩三分之二时间。” 阶段权重和剩余工作未必已知；假思考、不真实百分比与隐藏停滞会伤害可核对的信任。
  • “第一个字出来就是完成，留下的人更满意就算赢。” 内容、可用、完整与感知终点不同；完成者筛选和缺失反馈会扭曲判断。
  • “静默对照必须连失败都不说，模拟数据可以替代A/B。” 必要的受理/失败/取消能力应保持；合成事件只能验证实现与计算，不能制造真人行为或收益证据。

追问

每个追答均可单独展开。

追问 01

TTFT降低但投诉更多，怎么解释？

展开追答：TTFT降低但投诉更多，怎么解释？
追答

可能只是更早展示无用片段，后续停顿、内容反复或失败仍多；检查首个可用/完整结果、流中停顿、分群完成率和真实主观反馈。不能只优化一个首片段数字。

追问 02

无法得到准确进度，是否仍能反馈？

展开追答：无法得到准确进度，是否仍能反馈？
追答

可以报告已受理、已确认的阶段/计数、当前未知与取消选项；用不定进度表达正在等待，不编百分比、剩余秒数或模型思考故事。长期停滞则按事实说明尚未确认进展。

追问 03

流式片段已够用户使用，退出是否算失败？

展开追答：流式片段已够用户使用，退出是否算失败？
追答

先确定产品目标；若最小单元已经满足目标，应按预注册目标计完成，并另计后续完整输出。若目标需要全量，部分价值仍不能替代完成率；不能看结果后改口径。
