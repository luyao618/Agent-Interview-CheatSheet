AI 参考答案GPT-62026-09-15

参数量提供容量，数据决定训练看到哪些模式，计算预算决定这些容量能被训练到什么程度；最后还要用任务评测判断是否有用。 Scaling Law 是特定实验条件下的经验规律，不是“参数翻倍，所有能力都会按固定比例提升”的定律。选择一个更合适的模型，与证明“参数规模导致能力增长”，是两个不同的问题。

1. Scaling Law 描述什么，为什么不能只加参数

Kaplan 等人的工作研究语言建模交叉熵 loss 与模型规模、数据规模、训练计算量的关系，在其测试范围内观察到近似幂律。Hoffmann 等人的 Chinchilla 研究进一步讨论固定训练预算下，怎样分配参数与训练 token。其一种拟合形式为：

L_hat(N, D) = E + A / N^α + B / D^β
C ≈ 6 N D

N 是论文约定口径的模型参数数，D 是训练处理过的 token 数，C 是训练浮点运算量，单位为 FLOPs；E、A、B、α、β 需要从匹配的数据与训练配置中拟合。第一式是 loss 的经验模型，不是智力评分公式；Chinchilla 的该分析在数据充分的设置下用平滑训练 loss 估计测试 loss，不能把系数无条件移植到其他语料、tokenizer 或后训练模型。

第二式是 dense Transformer 训练的常用近似，主要反映参数相关的前向/反向运算，不能直接当作 GPU 小时、能耗、美元费用或所有架构的精确 FLOP 数；长上下文的注意力项、具体实现以及 MoE 的参数口径等需要另外核算。固定 C 时增大 N，能处理的 D 就会减少，所以可能得到一个容量更大、却训练不足的模型。

纯预算算例，非模型配置或报价（2026-09-15 核算）：假设方案一为 N=30×10⁹、D=100×10⁹，方案二为 N=10×10⁹、D=300×10⁹，代入近似式都得到 1.8×10²² FLOPs。这只表示估算训练算量相同，既不证明两者 loss 相同，也不证明第二个方案一定最优。下面的评测候选 G/S 没有真实训练账本，这组预算数值也不为它们提供成本证据。

Chinchilla 在其设置中支持参数与训练 token 随算力预算近似均衡增长，但不能提炼成“每个参数永远只该训练固定数量 token”。数据、目标和推理使用量改变时，最优点也会改变；大量部署请求可能使“多训练一些、换取更小的服务模型”更有价值。训练算力和推理时的长思考、多次采样、工具调用预算也应分开记录。

2. 数据规模之外，还要看质量与覆盖

D 增长不等于新增了同等数量的有效知识。重复遍历相同数据会增加处理 token 和计算量，却不自动增加覆盖；噪声、错误标签、过时事实和重复内容会影响学习效率。语言、领域、任务形式、稀有情况是否被覆盖，也会决定模型在哪些切片上表现好。参数不是数据库容量，不能用“读过多少字”直接推算“掌握多少事实”。

质量筛选同样有取舍：去重和过滤可能提高平均质量，但过滤过强也可能删掉少数语言、专业符号或长尾任务。应在固定训练配方下比较数据版本，并观察各切片，而非只看总 loss。DataComp-LM 提供的受控数据实验包含去重、过滤和混合策略，支持“数据设计需要实验验证”，不支持某一种过滤规则普遍最优。

训练/开发/测试集还要按文档、时间或业务实体隔离，并做近重复检查。测试题泄漏、用测试集反复调 prompt，或评测分布恰好匹配领域训练集，都可能让“小领域模型很强”看起来比实际可迁移能力更好。闭源训练数据不可见时，应把污染风险作为证据限制，不能声称已经完全排除。

3. 怎样判断“涌现”，而不是只看一条阶梯曲线

Wei 等人讨论的涌现指某能力在小模型上未出现、在较大模型上出现，且难由小模型分数简单外推。Schaeffer 等人则展示：对固定输出选择不同指标，可以让同一变化表现为突变或平滑增长；非线性、离散阈值、有限样本都会影响观测曲线。两者提醒我们区分观测到的得分突变与底层能力发生突变的解释。

判断时至少做三件事：

  1. 保留连续信息：除 exact match 或“通过/不通过”，还记录适用的部分正确分、编辑距离、数值误差或 log loss。不能强行给所有任务选同一指标；不同 tokenizer 下的 per-token loss 也不能直接当成同口径能力分数。
  2. 检查测量方式：展示原始逐题结果、样本量、误差区间，做事先规定的阈值敏感性检查，避免只挑最好看的任务或坐标轴。二值指标本身有业务意义，但不能单独承担机制解释。
  3. 增加受控规模点：在相近模型系列、数据与评测协议下比较多个规模和重复训练/采样结果，尤其补测所谓转折点附近。两个不同厂商的模型加一个成功案例，无法定位“能力在多少参数时出现”。

反过来，发现某个阶跃能由指标解释，也不等于证明所有能力变化都不存在。合理结论应限定为具体任务、模型系列、训练方式、指标和规模区间，不预设“涌现必然存在”或“全部都是幻觉”。

4. 大通用模型与小领域模型的配对评测

以“设备售后问答”为例，G 表示较大的通用候选系统，S 表示较小且做过领域适配的候选系统。这是评测方案设计，不是已执行的真实模型对决。 先固定版本、测试集及分析计划，再把每一个相同 case 同时交给 G、S，按 case ID 比较差值。

一条发给两个候选模型的输入 fixture 可以是：

资料：X20 主机保修 24 个月，滤芯等耗材不在保修范围。
问题：购买 18 个月后磨损的 X20 滤芯能免费更换吗？只按资料回答并引用依据。

另给评分器的参考要点是“识别耗材排除条款，不能只凭未满 24 个月判为免费”；这份答案要点不进入候选模型的输入，避免评测泄漏。

测试集还应包含跨条款问题、领域术语、资料不足应追问、未见故障类型，以及域外语言/算术等保留集。真实样本量应按最小关注差异和方差设计；下节的八项数据只供算术演示，不足以完成正式验收。

控制项 配对评测协议
输入与知识来源 同一 case、同一资料快照和语义指令；基础比较固定检索结果或关闭检索。生产全链路 RAG 可另设一条评测轨道
格式与调优 各模型使用自己的匹配 chat template；允许在同一开发集、相同调优预算内适配 prompt，然后冻结。不能为了“同一字符串”给某一模型套错模板
工具与推理预算 固定可用工具、调用次数、超时与输出要求；记录采样设置、重复次数及实际 token/工具消耗。同一 token 上限不保证不同 tokenizer 的内容预算或 FLOPs 相等
数据隔离 同一未用于训练/调优的测试集，按真实业务单位隔离近重复；领域内与域外分开报告
判分 预先定义共同 rubric，盲化模型名与展示顺序，记录逐题连续分和关键错误。若用模型裁判，先做人类校准，避免风格或自家模型偏好
聚合与不确定性 按 case 算 d_i = score_S - score_G，再按预先定义的流量权重汇总。真实数据可按工单/客户等独立单位做分层 paired bootstrap，保留配对与聚类结构
服务约束 在规定并发与缓存条件下测延迟、吞吐和实际成本；比较每个成功任务成本时纳入失败、重试和回退。当前示意数据不包含这些测量

这能支持候选系统选型，不能把差异归因于参数量。 G/S 的预训练数据、领域适配、架构和服务实现本来就不同。如果要研究规模作用，应另做同系列的受控训练实验，并先定义要回答的问题：

  • 固定训练 token 数 D，改变 N：保持数据分布、tokenizer、扩缩规则、训练/调优协议等可比，并重复训练。此时计算量通常随 N 增加，结论不是“固定算力下增大模型的收益”。
  • 固定训练计算预算 C，改变 N/D 分配：比较不同规模在该预算下的最优配置，回答的是资源分配问题；D 也在变，不能称为“只改参数量”。

在 C≈6ND 下，不能同时固定 C、D 又自由改变 N。即使受控实验成立，结论仍受模型系列、数据与训练区间限制，不能推广为所有产品的参数因果定律。

5. 人工配对数据：连续分、阈值和权重如何改变判断

下表全部分数由作者人为设定，不来自真实模型、裁判或 API。 假设共同质量 rubric 是 0–1 分，越高越好，D1–D4 为领域内，C1–C4 为域外；示例另假设没有关键错误，故“通过”暂定义为分数 ≥0.80。正式评测应将关键错误独立作为 gate，不能让高平均分抵消严重失败。

Case 切片 G 分数 S 分数
D1 领域内 0.84 0.90
D2 领域内 0.76 0.84
D3 领域内 0.79 0.83
D4 领域内 0.81 0.82
C1 域外 0.86 0.65
C2 域外 0.82 0.72
C3 域外 0.78 0.70
C4 域外 0.74 0.68

主情景预设领域内/域外流量权重为 80%/20%，另检查预设的 50%/50% 情景。权重应由目标业务分布决定，不能看完分数后随意调到某个模型获胜。将以下代码保存为 paired_eval_demo.py，运行 python3 paired_eval_demo.py，仅依赖标准库：

from decimal import Decimal as D

# 全部是人工示意分数，不是任何真实模型的评测结果。
rows = [
    ("D1", "domain", "0.84", "0.90"),
    ("D2", "domain", "0.76", "0.84"),
    ("D3", "domain", "0.79", "0.83"),
    ("D4", "domain", "0.81", "0.82"),
    ("C1", "general", "0.86", "0.65"),
    ("C2", "general", "0.82", "0.72"),
    ("C3", "general", "0.78", "0.70"),
    ("C4", "general", "0.74", "0.68"),
]
assert len({r[0] for r in rows}) == len(rows)
threshold = D("0.80")
stats = {}
for group in ("domain", "general"):
    pairs = [(D(g), D(s)) for _, bucket, g, s in rows if bucket == group]
    assert all(D(0) <= v <= D(1) for pair in pairs for v in pair)
    count = D(len(pairs))
    g_mean = sum(g for g, _ in pairs) / count
    s_mean = sum(s for _, s in pairs) / count
    paired_delta = sum(s - g for g, s in pairs) / count
    assert paired_delta == s_mean - g_mean
    g_pass = D(sum(g >= threshold for g, _ in pairs)) / count
    s_pass = D(sum(s >= threshold for _, s in pairs)) / count
    stats[group] = (g_mean, s_mean, g_pass, s_pass)
    print(f"{group}: G={g_mean:.4f} S={s_mean:.4f} paired_delta={paired_delta:+.4f}")

for domain_weight in (D("0.80"), D("0.50")):
    combined = [domain_weight * a + (1 - domain_weight) * b
                for a, b in zip(stats["domain"], stats["general"])]
    g, s, g_pass, s_pass = combined
    print(f"weight_domain={domain_weight:.2f}: G={g:.4f} S={s:.4f} delta={s-g:+.4f}; pass G={g_pass:.2f} S={s_pass:.2f}")

# 独立的阈值示意：连续分数平滑上升，二值显示却发生跳变。
scores = [D(s) for s in ("0.76", "0.78", "0.80", "0.82")]
print("threshold demo: scores=" + ",".join(map(str, scores))
      + " pass=" + ",".join(str(int(s >= threshold)) for s in scores))

# 仅按dense训练近似式计算；N为参数数，tokens_seen为训练处理的token数。
compute = [6 * 30_000_000_000 * 100_000_000_000,
           6 * 10_000_000_000 * 300_000_000_000]
assert compute[0] == compute[1] == 18_000_000_000_000_000_000_000
print(f"illustrative training FLOPs: large={compute[0]:.1e} small={compute[1]:.1e}")

真实运行输出（2026-09-15，macOS arm64，Python 3.11.8）：真实执行的只有这些人工数据上的算术，没有训练或调用任何模型。

domain: G=0.8000 S=0.8475 paired_delta=+0.0475
general: G=0.8000 S=0.6875 paired_delta=-0.1125
weight_domain=0.80: G=0.8000 S=0.8155 delta=+0.0155; pass G=0.50 S=0.80
weight_domain=0.50: G=0.8000 S=0.7675 delta=-0.0325; pass G=0.50 S=0.50
threshold demo: scores=0.76,0.78,0.80,0.82 pass=0,0,1,1
illustrative training FLOPs: large=1.8e+22 small=1.8e+22

主情景里，S 的加权平均质量分只高 0.0155 分，阈值通过率却高 30 个百分点；50/50 情景下，连续分结论又反过来。领域内优势不能替代域外覆盖，二值通过率也不能替代原始分数。独立阈值示例中的四个连续分只增加相同步长，却显示为 0,0,1,1；这些点不是某组真实参数规模的结果，只用来说明测量尺度可以制造阶跃。

据此应继续做真实评测，不能宣布 S 已胜出。 目前缺少代表性样本、置信区间、关键错误、服务性能与成本证据，也没有任何参数规模的因果证据。正式选型可以预先约定质量非劣界和各切片底线，再在满足质量约束的候选中比较延迟及每成功任务成本。

6. 两种合理选择及其边界

选择 适用条件 代价 / 不适用场景
较大通用模型 任务跨度大、长尾多，实测显示通用覆盖更符合需求 服务成本、资源和延迟可能更高，但需实测；不能仅因参数多就用于所有高频简单任务
较小领域模型 范围稳定、领域数据可信，域内质量和部署约束都通过评测 要承担数据维护、适配和域外失效风险；需求频繁跨域时不应靠域内均分兜底

也可评估领域模型加通用回退，但回退触发器本身要验证，不能假设它总能识别自己的错误；总成本必须包含重复调用。开放权重与托管 API 的其他取舍见 llm-0002，本题不把开放方式与模型大小绑定。

常见误区

  • “一个成功问答或厂商跑分，证明参数越大越好、能力必然突变。” 缺少控制变量、完整分布、重复实验与指标核查，不能支撑这些结论。
  • “Scaling Law 保证任何下游任务都按幂律改善。” 原始 loss 规律有实验条件，任务指标和实际产品效用还需测量。
  • “更多 token 就是更多独立、高质量知识。” 重复、噪声和覆盖差异会改变收益，数据污染还会虚增评测分数。
  • “同样 messages 和相同 token 上限，就控制了参数量之外的一切。” 训练数据、架构、template、tokenizer 和服务预算仍可能不同。

追问

每个追答均可单独展开。

追问 01

训练算力翻倍，是参数翻倍好，还是多喂数据好？

展开追答：训练算力翻倍，是参数翻倍好，还是多喂数据好？
追答

先在目标数据与训练配方下检查是否容量不足、数据不足或优化不足，再做小规模训练曲线和等算量比较。Scaling Law 可帮助估算配置，不能在没有拟合与验证的情况下套用固定 N:D 比例；还要考虑部署期的推理成本。

追问 02

准确率突然从接近零变得可用，能否认定涌现？

展开追答：准确率突然从接近零变得可用，能否认定涌现？
追答

先检查 exact match、阈值和评分方式是否放大了渐进改善，再看逐题连续指标、误差区间和转折附近的多个受控规模点。若现象跨合理指标、任务和重复实验都稳定，证据更强；仍需限定适用范围，不能从一张曲线推出普遍能力门槛。

追问 03

小领域模型在配对测试中赢了，能否证明大模型参数浪费？

展开追答：小领域模型在配对测试中赢了，能否证明大模型参数浪费？
追答

只能支持该系统在该业务协议下的表现比较。领域数据、微调、架构和推理预算都可能解释差异；若想归因于参数规模，需要另做定义清楚的受控训练实验。域内胜出也不能自动覆盖域外需求。
